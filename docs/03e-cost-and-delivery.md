# WithBiz AI 운영 비용과 개발 검증 계획

작성일: 2026-10-27 · STEP 3 예산 시나리오 · 비용 단위 USD/월, 세금 제외

## 비용 산정 기준

사용자 수만으로 AI 비용을 계산할 수 없으므로 처리량을 명시한다. 아래는 실제 청구액 예측이나 구매 승인이 아닌 설계용 시나리오다. 무료 체험·일회성 토큰 제공·캐시 할인·Batch 할인은 합계에서 제외했다.

| 항목 | 1천 사용자 | 1만 사용자 |
| --- | --- | --- |
| 기업 | 사용자당1개, 총1,000개 | 총10,000개 |
| 신규·변경 공고 | 하루100건, 월3,000건 | 동일3,000건 |
| 공고 요약·조건 추출 | 건당 입력3,000·출력600토큰 | 동일 |
| 후보 LLM 재평가 | 기업당 평균2건/일, 월60,000건 | 월600,000건 |
| 재평가 토큰 | 건당 입력1,500·출력300 | 동일 |
| 임베딩 | 공고당800토큰, 기업당500토큰을 월1회 | 동일 단가·규칙 |
| 이메일 | 사용자당 월8통, 총8,000통 | 총80,000통 |
| 기간 | 30일 | 30일 |

요약과 조건 추출은 한 번의 구조화 요청으로 합친 가정이다. 실제 첨부 길이·출력 길이·실패 재처리·프로필 변경 횟수에 따라 달라진다. 일평균2건 재평가는 신규·변경 후보의 가정이며 최초 프로필의20건 재평가 비용은 아래 별도 표시한다.

## 계산식과 결과

AI 요약: `3,000 × (3,000 × 2 + 600 × 10) / 1,000,000 = $36`.

재평가: `기업수 × 30 × 2 × (1,500 × 2 + 300 × 10) / 1,000,000`.

임베딩: `(3,000 × 800 + 기업수 × 500) × 0.02 / 1,000,000`.

| 비용 | 사용자1천 명 | 사용자1만 명 |
| --- | ---: | ---: |
| 요약·조건 추출 | $36.00 | $36.00 |
| 후보 LLM 재평가 | $360.00 | $3,600.00 |
| 임베딩 | $0.06 | $0.15 |
| Supabase 운영·스테이징 최소 | $35.00 | $35.00 |
| Vercel Pro 최소 | $20.00 | $20.00 |
| 이메일 | $20.00 | $47.00 |
| 위 항목 합계 | **$471.06** | **$3,738.15** |
| 최초 기업등록20건 재평가 추가비용 | $120.00 | $1,200.00 |

소수점 반올림은 표시 단계에서 적용했다. DB·전송량·서버 함수의 추가 사용료, 추가 좌석, GitHub Actions, Sentry 유료 사용, 도메인, 별도 백업 저장소, 환전·세금, AI 재시도·추가 첨부 처리 비용은 합계에 포함하지 않았다.1만 명이라는 이유만으로 기본 DB 성능이 충분하다고 보장하지 않는다. 부하 측정 후 compute·저장소·대역폭을 다시 산정한다.

기업당 재평가를2건에서20건/일로 올리면 재평가만 $3,600 / $36,000이 된다. 따라서 상위20건을 매일 무조건 호출하지 않고 `(기업 버전, 공고 revision, 모델·프롬프트 버전)` 기준 캐시를 사용한다. 매칭 정확도 목표를 충족하는 범위에서 호출량을 줄인다.

계정별 AI 월 예산과 경고80%·중단100%를 설정하는 설계다. 예산 소진 시 새 작업을 budget_blocked로 표시하고 기존 결과의 생성 시각을 유지한다. 예산을 넘겨 숨겨진 추가 호출을 하거나 임의 점수를 생성하지 않는다. 한도 값은 실제 운영자가 결정하며 현재 유료 서비스 가입·결제·배포를 수행하지 않았다.

## 임베딩 후보 비교 계획

| 후보 | 비용 비교 기준 | 현재 판단 |
| --- | --- | --- |
| voyage-4-lite | $0.02/100만토큰 | 저비용 후보. 한국어 공고 검색 품질 미측정 |
| voyage-4 | $0.06/100만토큰 | 품질 비교 후보. 더 비싸다는 이유만으로 더 적합하다고 단정하지 않음 |

기업5곳·공고50건의 동일 정답표로 후보 검색 Recall@20과 최종 Precision@10, 처리시간·토큰비용을 비교한다. 조건이 명백히 다른 공고가 벡터 상위권이라는 이유로 통과하지 않는지도 확인한다. 테스트 전에는 모델·차원을 최종 확정하지 않고 공급자 어댑터와 버전 구분을 설계한다.

API·Supabase·Claude·메일 연결은 사용자가 준비할 때 추가한다. 연결 전에도 UI·도메인 로직·계약 fixture 테스트는 진행할 수 있다. 운영 연결을 제외한 로컬 시연을 전체 MVP 출시 완료라고 부르지 않는다.

## 테스트와 출시 게이트

- Vitest: 날짜·마감 시각·모집 상태·중복 후보·소스별 계약·자격3상태·캐시 버전·알림 키.
- DB 통합: 마이그레이션 빈 DB적용, 제약·인덱스, 회원A/B·비회원·관리자·작업자 권한, 뷰·직접 API.
- Playwright: 공개 탐색, 로그인·기업 저장, 관심·캘린더·알림 설정, 일반 회원 관리자 차단, 모바일390px, 키보드·200%확대.
- 실제 공급자: 최소 호출로 인증·페이지 종료·변경·원문·첨부·AI출력·메일 전달을 별도 확인한다.
- 추천 품질: 기업5곳×공고50건 수작업 정답표, 기업별 Precision@10와 평균80% 목표. 현재 미실행이다.
- 장기 운영:3개 경로30일 연속 실행·실패 알림, 중복2%이하 목표. 샘플4건의 중첩 확인으로 대체하지 않는다.
- 성능: 모바일 대시보드 LCP3초이하 목표. Lighthouse 모바일 설정과 실제 모바일 환경을 함께 기록한다. 로컬 그림 렌더 시간은 성능 지표가 아니다.

## 운영 연결 체크

로컬·스테이징·운영 프로젝트와 비밀값을 분리한다. 공개 변수는 Supabase URL·publishable key와 비밀이 아닌 기능 표시 설정만 둔다. 서비스 권한 키·공공데이터·Claude·임베딩·Resend·내부 서명키는 서버 전용이다. 모노레포 웹앱이 루트 환경 파일을 자동으로 읽는다고 가정하지 않고 명시적 실행·배포 변수 연결을 구현한다.

DB 자동 백업과 별도 주간 덤프·복원 시험, 소스 실패·0건·작업정체·AI예산 알림, 키 마스킹·로그 보유기간을 운영 안내에 포함한다. 정기 작업은 수집06:00·알림08:00 KST를 UTC로 정확히 변환하고 실제 실행 지연도 로그에 기록한다. 스케줄러 등록과 실제 메일 발송은 아직 수행하지 않았다.

## STEP 3 산출물 검증 기록

설계 문서의 내부 링크·주요 API 이름·테이블 관계를 대조했다. 데스크톱·모바일 대시보드와 상세 화면 PNG3개를 렌더하고 직접 검토했다. 핵심 색상 쌍8개가 대비4.5:1이상을 통과했다. 원본 성공색 대비4.45:1은 수정 후5.07:1이다. 근거는 `docs/design/wireframes/verification.json`이다.

현재 결과는 문서·정적 설계 검증이다. 앱 빌드·DB실행·RLS·브라우저 조작·성능·실제 추천 품질·백업복원 시험은 구현 후 수행한다.
