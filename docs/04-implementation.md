# STEP 4 구현 기록

## 배포 구조

사용자의 GitHub 저장소 `Choongsik-Yoo/WithBiz`를 기준으로 Next.js 정적 내보내기와 GitHub Pages를 사용한다. Supabase 프로젝트 `uqlaropgcluedhctzcao`, 서울 리전, 무료 요금제로 인증·데이터를 저장한다. 해시 기반 탐색으로 상세 화면 URL 새로고침도 정적 호스팅에서 유지한다. 원천 API 수집은 GitHub Actions 서버 작업으로 분리했다. 이전 설계의 Route Handler/서버 호스팅 방식에서 조정했다.

## 확인한 내용 (2026-10-27)

- 공식 MSS API 전체 1,420건 조회 및 정규화·Supabase 저장
- Next.js 프로덕션 정적 빌드, 전체 TypeScript 검사 통과
- 날짜/KST/주간 마감·정규화·중복 해시·불확실성·벡터 유효성 8개 테스트 통과
- 임시 사용자 2개로 기업 소유권, 타인 조회/수정 차단, 오래된 버전 충돌, 관심 저장 격리/소유자 위조 차단, 관리자/수집 RPC 접근 차단 확인. 테스트 계정은 삭제
- 익명 사용자가 실제 공고 1,420건을 읽고 기업 테이블은 읽지 못함을 확인
- Supabase DB 권한 검사에 ERROR/WARN 없음. private 테이블 8개는 일반 사용자 접근을 막기 위해 정책 없는 RLS를 의도적으로 유지 (INFO). Auth 검사에는 유출 비밀번호 차단 비활성 WARN이 있으며, 이 기능은 [Pro 이상 요금제에서 제공](https://supabase.com/docs/guides/auth/password-security)되어 무료 프로젝트에서는 보류
- 브라우저에서 대시보드에 진행 공고 1,263건, 이번 주 마감 184건 및 실제 제목 표시 확인
- 브라우저 스크린샷 기능은 CDP 시간 초과로 사용 불가. DOM과 화면 크기·요소 상태를 기준으로 기능 확인
- GitHub 암호화 Secrets와 Pages GitHub Actions 배포 소스, Supabase 인증 복귀 URL 설정
- GitHub Actions 프로덕션 테스트·빌드·배포 성공. 공개 주소에서 실제 대시보드, 키워드 검색, 상세 원문 링크 동작 확인
- 모바일 폭 390px에서 상세 화면의 가로 넘침 없음. 로그인 및 기업 프로필 저장을 실제 브라우저에서 확인
- 실제 브라우저에서 관심 저장·검토 메모 저장·알림 수신 설정 저장 확인. 임시 계정과 소유한 테스트 데이터 삭제 완료

## 완료 기능

대시보드·지도·공고 목록과 필터·상세·관심/메모·달력·기업 프로필·조건 기반 추천·이메일 인증·알림 설정 저장·출처·관리자 화면을 작성했다. 개인 데이터는 RLS와 인증 사용자 기반 RPC로 보호한다. 숨김 변경은 감사 이력을 남긴다. 가입 동의 버전을 저장한다. PWA는 정적 셸만 캐시하며 개인 API 데이터는 캐시하지 않는다.

## 연결 또는 후속 개발 항목

- K-Startup API 인증 재검증 및 수집 활성화
- Anthropic/Voyage 키와 운영 모델 확정. 제공자 어댑터는 있으나 AI 요약 작업·벡터 후보 단계·실사용 품질 평가는 미완료
- 현재 선택형 매칭 배치는 규칙 후보 상위 20건을 재평가하며, 월 $100의 보수적 예약 한도를 둠. 실제 토큰 정산/모델별 예산 보정은 후속
- 이메일 제공자·검증된 발신 주소 연결 및 실제 발송/재시도/중복 방지 구현. 현재 설정만 저장하고 발송 이력은 생성하지 않음
- Google OAuth, 계정 삭제 UI, 운영자 연락처/정식 약관·개인정보 문서 확정
- 일반 외부 사용자의 가입 인증 메일을 위한 운영 SMTP 연결과 전달 검증
- 사용자별 다수 기업 전환, 대규모 서버 검색/페이지네이션, 접근성·설치형 PWA의 기기별 실사용 검증

기능 미연결 항목을 화면에서 준비 중으로 표시하며 가상의 공고·AI 점수·발송 성공 기록은 넣지 않는다.
